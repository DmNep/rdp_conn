# rdp_conn

Контекст для ИИ-агента. Читать до правок. Владелец — Дмитрий (DmNep).

## 1. Что это

Канал управления между двумя Windows-машинами через **буфер обмена RDP**.
Отправитель (`rdpconn.tx`) сидит на машине с запущенным mstsc, приёмник
(`rdpconn.rx`) — внутри RDP-сессии. Команда уходит кадром `CMD`, обратно идёт
`ACK` (кадр дошёл) и `NOTE` (вывод команды).

Канал нужен ровно тогда, когда между машинами остался только RDP. На стенде,
где он проверялся, не работает ни одно плечо звука, а из сети наружу разрешён
только порт 3389 — то есть сам RDP. Буфер обмена живёт внутри того же
соединения: порты, брандмауэр, права администратора и звук не нужны.

Формат обмена — `docs/protocol.md`, единственный источник истины. Значения
протокола числом заданы только в `rdpconn/config.py`; расхождение кода со
спецификацией считается ошибкой кода. Номера разделов спеки используются в
комментариях исходников (`docs/protocol.md 4`), их менять нельзя.

## 3. Стенд

| | Машина A (отправитель) | Машина B (приёмник) |
|---|---|---|
| Где | Windows, клиент mstsc | RDP-сессия, Windows |
| Код | `C:\Users\d.proskurnin\projects\rdp_conn` | `D:\Users\d.proskurnin\Documents\x_conn2_portable` |
| Python | системный 3.12 | 3.13 |

Живой канал — только буфер обмена: звук мёртв с обеих сторон, сеть кроме 3389
блокируется, `\tsclient\` недоступен.

Прогон:

```text
B: cd D:\Users\d.proskurnin\Documents\x_conn2_portable
   $env:PYTHONPATH="$PWD"; python -m rdpconn.rx --peer-id B --exec

A: cd C:\Users\d.proskurnin\projects\rdp_conn
   $env:PYTHONPATH="$PWD"; python -m rdpconn.tx --peer-id A --reply-wait 2.0 --repl
```

Две вещи, без которых прогон бессмыслен:

- **На B ровно один `rx`.** Два приёмника с одним `--peer-id` дают лавину
  подтверждений на каждый кадр: обмен визуально работает, но тонет в повторе.
  Признак — шторм `>> PONG` и удвоенные `<< ACK` у отправителя. Это окружение, а
  не код: так выглядит любая исправленная ошибка, если не проверить число
  процессов (`tasklist /fi "IMAGENAME eq python.exe"`).
- **`--peer-id` задан на обеих сторонах.** Без него метка случайная, и каждый
  перезапуск стороны выступает под новым id; старые ячейки остаются в слоте
  чужим наследием.

## 5. Проверки

Скрипты без зависимостей, системный python, каждая завершается строкой
`RESULT: ALL GREEN`:

```text
cd C:\Users\d.proskurnin\projects\rdp_conn
set PYTHONPATH=%CD%
python tools\test_frames.py       # кадр, CRC, разбор, коды NAK, точка входа
python tools\test_clipboard.py    # слот: маркер, история, пауза, занятость, restore
python tools\test_heartbeat.py    # PING/PONG, молчание, возврат после обрыва
python tools\test_duplex.py       # tx и rx двумя процессами через один слот
```

`--slot file:PATH` заменяет буфер обмена файлом — на этом держатся все четыре:
хранилище отслоено (`WindowsClipboard` / `MemoryClipboard` / `FileClipboard`),
поэтому маркер, история, занятость и пауза проверяются без Windows API и без
второй машины.

`test_frames.py` содержит секцию сверки кадров с `xconn_channel.framing`
(байт-в-байт). Она сама пропускается, когда `xconn_channel` недоступен, — так и
должно быть при запуске из этой папки.

## 6. Что здесь уже ломалось (регрессии, закрытые тестами)

Стоит знать перед правкой, иначе легко вернуть:

- **Принятый кадр не должен теряться на служебной логике.** Первая потеря CMD на
  живом буфере: кадр читался, обрабатывался heartbeat-ом и не доходил до
  обработки, потому что после `heartbeat_tick` стоял `continue`. Приём и разбор
  собраны в `rx.step`; регресс проверяет, что `PING` не съедает уже принятый кадр.
- **Запись в слот перечитывается прямо перед записью.** Буфер не даёт атомарного
  «прочитать и изменить», поэтому номер буфера сверяется непосредственно перед
  записью, при расхождении текст собирается заново (`PUBLISH_TRIES = 3`).
  Раньше merge строился по тексту, прочитанному до записи, и параллельная запись
  собеседника затиралась.
- **Ответная сторона не заводит своих `PING`** (`Heartbeat(proactive=False)` на
  приёмнике). Двусторонний пинг удваивает записи в слот, каждая запись — ещё и
  событие RDP-редиректа; на лагающем редиректе heartbeat сам мешает обмену.
- **`--ping` ниже 10 ломает канал на живом редиректе.** Буфер в RDP запаздывает
  сам на 10–15 с; порог молчания — `--ping` × 3, по умолчанию 25 × 3 = 75 с.
  Порог ниже `MIN_SILENCE_S = 30` помечается предупреждением, а не молча
  меряется.
- **Кириллица — только в cp866** (`config.CODEPAGE`). В cp437 кириллицы нет
  вовсе, и `errors="replace"` превращала текст в `??????` ещё до отправки.
  Симметричные места: вывод `--exec` читается байтами и декодируется явно
  (`text=True` в subprocess декодировал бы его cp1251), эхо возвращает payload
  байт-в-байт.
- **`tools/test_duplex.py`: `start()` обязан давать `stdin=subprocess.PIPE`**,
  иначе REPL получает EOF и тест начинает зависеть от терминала.

## 7. Соглашения

- Язык документации, комментариев и сообщений — русский. Идентификаторы —
  английский. Файлы — UTF-8.
- Комментарии — редко и про *зачем*, а не про *что*. Почти каждая константа
  объяснена числом и причиной; новые комментарии этот стиль не должны ломать.
- Стиль докстрингов — «почему так, а не иначе», с указанием на наблюдаемое
  поведение. Коротких пересказов кода не нужно.
- Тесты — скрипты с `check(...)` и итогом `RESULT: ALL GREEN`, не pytest:
  зависимостей нет, интерпретатор на второй машине «как есть».
