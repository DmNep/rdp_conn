# rdp_conn

[![license: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

Канал управления между двумя Windows-машинами через **буфер обмена RDP**.

Нужен ровно тогда, когда между машинами остался только RDP. Проверялось на
стенде, где на одной стороне захват звука отдаёт 0 устройств из 19, на другой
политика запрещает запись, а из сети наружу разрешён только порт 3389 — то есть
сам RDP. Буфер обмена живёт внутри того же соединения, поэтому каналу не нужны
ни открытые порты, ни звук, ни права администратора.

```
машина A (клиент mstsc)  ── RDP, редирект буфера ──  машина B (сессия)
       rdpconn.tx          ──── кадры с CRC ────       rdpconn.rx --exec
```

Команда уходит кадром `CMD`, обратно приходит подтверждение `ACK` и вывод
команды `NOTE`. Никаких сокетов: один текстовый слот, в котором живут последние
кадры обеих сторон.

## Установка

Нужен только Python 3.10+. Внешних зависимостей нет намеренно: канал нужен
ровно тогда, когда на второй машине нельзя ничего поставить и поднять.

```text
git clone https://github.com/DmNep/rdp_conn.git
cd rdp_conn
set PYTHONPATH=%CD%
```

Ставить пакет не обязательно — `python -m rdpconn` работает из каталога.

## Быстрый старт

Сторона B — приёмник, внутри RDP-сессии:

```text
python -m rdpconn rx --peer-id B --exec
```

Сторона A — отправитель, на машине с запущенным mstsc:

```text
python -m rdpconn tx --peer-id A --repl
```

Метка `--peer-id` обязательна на обеих сторонах и не по вкусу: без неё метка
случайная, и каждый перезапуск стороны выступает под новым id, а собеседник
теряет возможность сопоставить кадры одного конца до и после перезапуска.

На B держите ровно **один** `rx`. Два приёмника с одним `--peer-id` дают лавину
подтверждений на каждый кадр: обмен визуально работает, но тонет в повторе.

## Что происходит на одном шаге

| Шаг | Кадр | Смысл |
|---|---|---|
| 1 | `CMD seq=0` | текст команды |
| 2 | `ACK seq=0` | кадр дошёл (не «команда выполнена») |
| 3 | `NOTE seq=0` | вывод команды, пакетами по 240 байт |

Без `--exec` на третьем шаге уходит эхо принятого текста байт-в-байт — дешёвая
проверка, что кодовая страница сторон не разъехалась.

## Ключевые флаги

| Флаг | Сторона | Зачем |
|---|---|---|
| `--peer-id A\|B` | обе | метка конца в слоте, обязательна в бою |
| `--exec` | rx | исполнять команду и возвращать вывод |
| `--repl` | tx | читать команды с клавиатуры |
| `--hotkey ctrl+alt+f9` | обе | отдать буфер человеку, повторное нажатие продолжит обмен |
| `--ping 25` | tx | интервал контрольных кадров; меньше 10 не ставить |
| `--slot file:PATH` | обе | слот в файле: проверить весь обмен одной машиной |
| `--codepage cp866` | обе | кодовая страница текста |

`--ping` ниже 10 ломает канал на живом редиректе: буфер в RDP сам по себе
запаздывает на единицы-десятки секунд, и живой собеседник объявляется
потерянным. Порог молчания — `--ping` × 3.

Хотите копировать своё и не мешать обмену — не ставьте `--hotkey`: приёмник
заметит человеческую копию, скажет о ней, но подтверждение всё равно отправит.
Буфер отдать целиком можно только клавишей.

## Проверка без второй машины

`--slot file:PATH` заменяет буфер обмена файлом, и оба конца запускаются на одной
машине. Хранилище отслоено, поэтому маркер, история слота, занятость и пауза
проверяются без Windows API.

```text
python tools/test_frames.py      # кадр, CRC, разбор, точка входа
python tools/test_clipboard.py   # слот: маркер, история, пауза, занятость
python tools/test_heartbeat.py   # PING/PONG, молчание, возврат после обрыва
python tools/test_duplex.py      # tx и rx двумя процессами через один слот
```

Все четыре — скрипты без зависимостей, завершаются `RESULT: ALL GREEN`.

## Ограничения

- **Шифрования и аутентификации нет.** Буфер читает любое приложение сессии;
  метка стороны защищает от рассинхронизации, а не от чужого процесса. Для
  чувствительных команд канал не предназначен.
- **Кадру нужно быть текстом**, поэтому он в base64: 240 байт кадра дают ~330
  символов в буфере.
- **Файлы и терминал не передаются.** `--exec` — запуск одной команды с
  возвратом вывода; для файлов есть сам RDP.
- **Один отправитель на слот.** Ячейки подписаны, но очередь на подтверждение
  одна.

## Состав

| Путь | Назначение |
|---|---|
| `rdpconn/config.py` | значения протокола: единственный источник истины |
| `rdpconn/crc.py` | CRC-16/CCITT-FALSE |
| `rdpconn/framing.py` | сборка и разбор кадра, коды отказа |
| `rdpconn/clipboard.py` | слот: маркер, история, занятость, пауза, горячая клавиша |
| `rdpconn/app.py` | аргументы, обмен, heartbeat, вывод |
| `rdpconn/tx.py` | отправитель |
| `rdpconn/rx.py` | приёмник |
| `docs/protocol.md` | спецификация канала |
| `tools/` | проверки без второй машины |
| `tools/make_portable.py` | архив для машины без интернета |

## Переносной архив

```text
python tools/make_portable.py
```

Архив `rdp_conn_portable.zip` содержит пакет и инструкцию. Интернет на второй
машине не нужен: зависимостей нет, достаточно распаковать и задать `PYTHONPATH`.
